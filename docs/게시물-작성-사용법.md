# 수리공 게시물 작성 프로그램

## 할 수 있는 일

- `/admin/posts`에서 현장 정보 입력 → 사이트용·네이버용 기본 초안 자동 작성
- 제목·본문 수정, 사진 최대 6장 축소와 단계·설명 지정
- 초안 JSON 파일 저장·불러오기: PC방에서 저장한 파일을 노트북에서 불러와 이어서 작성
- 관리자 비밀번호로 확인 후 사이트 게시 → `/cases` 목록과 상세 페이지
- 네이버용 글 복사 → 네이버 편집기에서 원본 사진 첨부 후 직접 발행

글 생성은 입력한 사실을 정해진 문장 틀에 정리하는 방식입니다. AI 호출, 네이버 자동 로그인·발행, 예약 게시 기능은 포함하지 않습니다. 현장 내용을 바꾸면 기존 초안이 초기화됩니다. 초안을 먼저 파일로 저장하면 원본을 보관할 수 있습니다.

## 첫 설정 (Vercel 사용 시)

1. GitHub의 이 변경사항을 main에 반영한 다음 Vercel 배포가 성공했는지 확인합니다.
2. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
3. Repository access에서 **Only select repositories → surigong-web** 선택. Repository permissions의 **Contents → Read and write**만 허용합니다. 토큰 만료일도 설정합니다.
4. Vercel → surigong-web 프로젝트 → Settings → Environment Variables에 아래 두 항목을 추가합니다.
   - `SURIGONG_ADMIN_PASSWORD`: 무작위 16자 이상 비밀번호. 비밀번호 관리자 사용을 권장합니다.
   - `SURIGONG_GITHUB_TOKEN`: 방금 발급한 토큰.
5. Production 환경에 적용하고 Redeploy합니다. 실제 비밀번호와 토큰은 대화·소스·스크린샷에 공개하지 마세요. NEXT_PUBLIC_ 접두사를 붙이지 않습니다.
6. `https://수리공.kr/admin/posts`를 열고 글을 작성합니다. 발행 성공 메시지와 게시물 주소를 확인하세요.

## 사진·공개 범위

사진은 긴 변 1000px 이내 JPEG로 변환하고 파일당 약 75KB 이하로 압축합니다. 글마다 최대 6장입니다. 게시 글과 사진은 공개 GitHub의 `data/work-posts/<게시물번호>.json`에 저장되어 커밋 이력에도 남습니다. 초안 파일은 로컬에만 저장되며 비밀번호를 포함하지 않습니다. 사진 원본은 별도로 보관하고 고객의 상세 주소·연락처·미동의 얼굴 사진을 게시하지 마세요.

게시 후 수정/삭제 UI는 현재 포함되지 않습니다. 관리자만 GitHub에서 해당 JSON을 수정하거나 삭제할 수 있습니다. 삭제해도 커밋 이력에는 남으므로 민감한 정보를 처음부터 넣지 않아야 합니다.

## 검색 등록

기존 sitemap.xml은 유지됩니다. 네이버 서치어드바이저 사이트맵 제출에 `https://수리공.kr/cases/feed`를 추가하면 게시된 작업사례 URL 목록을 제공할 수 있습니다. 검색 등록이나 상위 노출은 보장하지 않습니다.

## 운영 조건과 한계

Next.js 서버가 필요하며 정적 파일 호스팅만으로는 게시 API가 작동하지 않습니다. GitHub 토큰은 게시 시 서버에서만 사용합니다. GitHub 연결이 실패하면 게시 성공으로 표시하지 않습니다. 동일 게시물의 재시도는 중복 등록하지 않습니다. 목록은 GitHub API로 글을 읽으므로 초기 소규모 운영에 적합하며, 글이 많아지면 DB·사진 저장소로 이전해야 합니다. GitHub Contents 디렉터리 API는 최대 1,000개 항목을 지원하며 이 수 이전에 이전해야 합니다. 발행 시 main에 커밋이 생겨 연결된 배포 시스템의 재배포가 발생할 수 있습니다.
